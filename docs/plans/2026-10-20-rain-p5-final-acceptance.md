> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

## 4. 逐模块适用状态核对规则

每个矩阵行至少核对以下适用维度，并记录实际证据文件、版本摘要、环境和结论：

- 默认、真实指针hover、键盘focus-visible、pressed／selected、disabled、readOnly、invalid及其组合；不适用时说明组件设计原因。
- 文本输入、清除、必填错误、纠错后错误消失；选择控件的选择／取消、禁用跳过和受控值；列表的空态、长内容、适用的异步／大数据路径。
- 浮层打开、内部Tab路径、Escape、关闭焦点、滚动、嵌套与portal主题；日期内部面板关闭与整个浮层关闭分别验。
- 原版Light／Dark和Rain恢复；长中文、固定宽／窄容器、字体回退、焦点／错误信息可辨识。
- CSS fixture只能证明样式规则；看到快捷键文本不能算快捷键已注册；开发态story可打开不能算生产产物存在。

Card、Surface、Separator等不拥有的状态不得新增一套伪交互。Card内部按钮的disabled／focus，不记录为Card容器自身的disabled／focus状态。辅助模块通过公开API或父组件证明，不为了验收数量另造视觉样例。
