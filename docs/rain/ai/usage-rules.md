# AI 组合与改造规则

## 修改顺序

1. 复用当前版本的组件与示例。
2. 在业务层组合，状态与数据保留在业务层。
3. 出现多处真实复用时提取业务组件。
4. 公开 API 确实不足时才修改基础组件，并记录上游差异和受影响状态。

不为全库创建 RainButton／RainInput 空包装，不复制第二套 HeroUI 组件，不更换固定版本或擅自添加新的 UI 框架。

## 三类改动的入口

| 目标                             | 修改位置                                                                    | 需要保持的行为                             |
| -------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------ |
| 品牌颜色、字体族、圆角           | `packages/rain-theme/index.css`                                             | 根作用域与 portal 继承、原版主题可恢复     |
| 页面、列表、卡片、批改等业务组合 | `apps/docs/src/components/rain-examples/` 或实际消费者的业务目录            | 学生／记录间状态隔离、表单校验、显式提交   |
| 基础组件 API 或行为              | `packages/react/src/components/`；对应 CSS 在 `packages/styles/components/` | 标签、键盘操作、焦点、禁用、只读与错误语义 |

`.tsx` 添加 `"use client"`；组合布局放在 `.styles.ts`，使用 `tailwind-variants`。页面使用已有 semantic utility 和组件变体，不硬编码品牌色、字体族或组件圆角。

## 本版本常见用法

- 导入来自 `@heroui/react`；具体名称以组件入口和根导出为准。内部 helper 不应臆造根导入名或发布子路径。
- TextField 组合 Label、Input／TextArea、Description、FieldError；Form 负责提交，业务层决定是否开启确认浮层。
- Select、ListBox 使用本地 v3 示例中的复合结构和受控值。不要套用旧版 NextUI 的 SelectItem／ModalContent 等 API。
- Modal／Popover 的内容通过 portal 出现，雨课堂主题应在 html 根节点启用；普通局部 div 不能隔离整套主题。
- 原版与雨课堂同时并排时使用独立 iframe。普通切换使用已有主题控制器，不手工叠加重复 class 或 inline 颜色。
- 消费宿主按语义变量绑定正文色和字体（例如 `color: var(--foreground)`、`font-family: var(--font-sans)`），并覆盖 body portal 的继承链；不要逐个给裸文字组件追加品牌样式。文档站与 Storybook 已分别处理该宿主绑定。
- 复制／组装示例时保留上游合理的交互机制，不能以统一视觉为由隐藏焦点或吞掉错误状态。

用户明确要求的 Tabs 例外：本地 Tabs.Tab 为普通文本／数字及 Fragment 中的连续文字提供 `tabs-label` 包装；Rain 下单行、最长 14em、溢出省略，实际截断时悬停用原生 title 展示全名。Indicator／Separator 和自定义元素不放进裁剪层。任意富文本自定义元素仍由业务调用方管理布局，不递归改写其内部。完整可访问名称、方向键和禁用选择守卫保留；原生 title 不增加键盘聚焦弹层或额外焦点目标。用户本次“确定。继续推进”只确认当前表格 `#EBEFFF`／`#7485A8` 和普通 Tabs 名称反馈，不扩展为全库状态或生产验收。

跨项目私有交付为 `delivery/rain-heroui-local-2026-10-20-r2/`，React／Styles `3.2.6-rain.1`、主题 `0.1.2`，源码上游仍为固定 HeroUI 3.2.6。r2 已生成私有归档并完成限定消费验证：真实归档的根／子路径导入、Tabs 标签 SSR／样式槽、Bundler 示例与负例类型、包内 CSS 编译及主题源码 SHA 核对通过。此结果只覆盖记录中的产物与消费路径；浏览器、全库状态和生产验收分别记账。旧 0.1.1 归档保持历史冻结状态，不含这两个 Tabs 源码补丁与当前表格配色；不能仅更新旧包 CSS 就推断能力齐全。实际交付范围读取 `docs/rain/consumer-verification.md` 与相应交付目录的 README、manifest、report。

## 索引的边界

组件中心与结构化目录来自 `docs/rain/inventory.json`。记录的 story ID 优先取现有构建索引；引用父组件／组合 story 时会明确标记。英文回退标明实际语言，缺少独立资料的模块仍保留源码入口，不制造空白文档或假预览。

组件中心的“固定版本上游源码”指向冻结提交；本地当前实现以目录内的真实文件为准。业务示例和新雨课堂主题尚未发布到上游，不能把它们当作官方资产。

## 验证与报告

按改动影响范围选择必要的单文件检查和页面抽查；通过后不反复扩大测试范围。当前不运行新的重测试、全库 story 扫描或生产构建。

报告应写明：改了什么、实际跑了哪些检查、用户审核覆盖哪个页面、哪些事项仍待验证。已有历史测试结果不自动适用于后续变更。不要提交、推送、发布、替换旧业务或接入真实成绩服务，除非用户明确提出。
